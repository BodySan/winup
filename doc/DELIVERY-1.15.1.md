# WinUp 1.15.1: изменения и приёмка

## Исправления

- Исправлен реальный отказ Google до подтверждения: длинный challenge отклонялся пределом 1024 байта. Теперь допускается до 8192 байт в пределах ограниченного сообщения; отдельный тест проверяет подпись и полное сохранение 4096-байтового challenge.

- Повторный вход отменяет прежнюю незавершённую попытку. Выбранный сайт открывается в новом запросе выбранного браузера; пакетный вход сохраняет отдельные запросы.
- Уточнены публичные маршруты и кнопки входа шаблонов. Главные адреса известных сервисов обновляются на их маршруты входа; собственные адреса с отдельным путём сохраняются.
- Исправлены многошаговое заполнение и предложения сохранения после перехода или замены формы. При общем провайдере входа требуется выбор нужной записи. Повторный ввод снова предлагает сохранить или обновить пароль.
- Исправлен длинный список аккаунтов, выходивший за окно Opera. Список прокручивается в пределах окна.
- Включено постоянное расширение Firefox 1.6.6 с подписью Mozilla. В окне настройки доступны about:addons и показ проверенного XPI.
- Обновлён интерфейс: светлая палитра, синие главные действия, одинаковые кнопки и поля, заметная выбранная вкладка, строка состояния. Нативные элементы Windows сохранены.
- Инструкция дополнена ответами про типы записей, второй логин, пути приложений, ключи доступа, Firefox, обновления, файлы и передачу пустой копии друзьям. Вопросы для следующего обсуждения собраны отдельно.
- Файловый адаптер согласован с приложением по API 4. Требуется новый комплект для WinUp 1.15.1; смешивать прежний адаптер с новой программой нельзя.

## Проверки в Windows Sandbox

Личная база владельца не открывалась. Использовались отдельные учебные базы, файлы, установщики и браузерные профили.

- 189 обычных функциональных проверок: 0 ошибок; повторный прогон выполнен после изменения интерфейса.
- Chrome, Edge, Brave, Яндекс и Opera: по 31 браузерному сценарию; Firefox: 32. Проверены заполнение, 2FA, сохранение, обновление без дубля, отказ, повторный ввод, два шага, замена формы, независимый WebAuthn и длинный список.
- Во всех шести браузерах проверено заполнение исходной формы после настоящего видимого диалога подтверждения WinUp.
- Настоящая кнопка «Войти» проверена в Chrome и Brave после полного закрытия браузера: второй выбор открывает второй адрес. Учебный адрес не содержит форму входа; этот сценарий проверяет запуск и выбор страницы.
- Подписанное дополнение Firefox установлено постоянно с обязательной проверкой подписи. Полный перезапуск сохранил дополнение, сопряжение и канал WinUp.

Подробности исправлений и внешний Google: [LOGIN-CORRECTIONS-1.15.1.md](LOGIN-CORRECTIONS-1.15.1.md). Следующие вопросы и источники сценариев: [QUESTIONS-AND-UX-2026-10-08.md](QUESTIONS-AND-UX-2026-10-08.md).

## Ограничения

Google принял регистрацию ключа WinUp в предоставленном тестовом аккаунте. Повторный вход этим ключом ещё не подтверждён. После исправления длинного challenge Google присылает три разрешённых ключа; зарегистрированный ключ WinUp среди них не найден. Возможная причина — период доверия нового ключа до семи дней, описанный в [справке Google](https://support.google.com/accounts/answer/13548313?hl=ru); именно причина для этого аккаунта не подтверждена. Для ускоренного подтверждения требуется уже доверенный способ владельца. Телефонный QR и аппаратные Windows Hello зависят от устройств владельца и не объявляются проверенными.

Публичные маршруты изучены; закрытые этапы всех сервисов, SMS и CAPTCHA полностью не проверены. Типовые тесты не доказывают исправность всех сочетаний действий и всех сайтов.

Новые атаки и углублённая проверка безопасности отложены по последнему распоряжению пользователя. Функциональная приёмка не является заключением об отсутствии всех уязвимостей.

Ключ подписи выпусков остаётся только на ПК владельца. GitHub выполняет проверки; подпись производится локально. Порядок обновления и риски: [UPDATES-SIMPLE-RU.md](UPDATES-SIMPLE-RU.md).

# WinUp 1.18.1

Исправлена выдача паролей сайтам, которые используют тот же домен, но другой протокол, порт или отдельный адрес `www`. Теперь такой адрес требует подтверждения. Адреса входа, предусмотренные шаблоном сервиса, продолжают работать.

- Разрешение на заполнение запоминается для полного адреса службы. Старые разрешения только для имени сайта нужно подтвердить заново.
- Сохранение и обновление пароля различают службы на разных портах.
- В подтверждении вставки пароля или кода 2FA показан адрес с протоколом и портом.
- Импорт 2FA ограничен 8 МБ, включая вставленный текст. Слишком большие и чрезмерно вложенные файлы отклоняются; обычные экспорты UTF-8 и UTF-16 поддерживаются.
- Инструкция дополнена ограничениями защиты файлов от подмены и обновлённым порядком подтверждения адресов.

Проверка выполнена на учебных данных в Windows Sandbox. Полный набор проверок приложения прошёл без ошибок. Отдельно проверены выдача паролей после подтверждения адреса, отказ для другого порта, вход через Google для YouTube и ограничения импорта 2FA. Эти проверки добавлены в процесс подготовки следующих выпусков.

## Ограничение файлового хранилища

Формат Cryptomator защищает содержимое от раскрытия, но не связывает содержимое файла с его именем. Если кто-то может изменять зашифрованные файлы, он может поменять местами содержимое двух документов в одной папке. Эта возможность воспроизведена на учебном хранилище; пароль и открытые данные не раскрывались. [Описание ограничения разработчиками Cryptomator](https://github.com/cryptomator/cryptomator/security/advisories/GHSA-qwfw-w5qf-7wcj).

Для передачи отдельного файла или папки предусмотрен зашифрованный пакет с проверкой содержимого и списка имён. Для работающего хранилища нужны резервные копии: шифрование не предотвращает удаление или возврат старой зашифрованной копии.

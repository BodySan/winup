# Обновления WinUp: что нажимать и кому что делать

GitHub здесь хранит исходники и файлы выпусков, а ещё запускает тесты на отдельной машине. Он не получает вашу базу паролей. Программа скачивает уже подготовленный комплект и проверяет его подпись.

## Варианты

| Вариант | Ваши действия | Что происходит | Ограничение |
|---|---|---|---|
| Получить файл от владельца | Получить `.wup`, выбрать его в окне обновлений, перезапустить WinUp | Программа проверит подпись и совместимость, подготовит компоненты | Каждый новый файл нужно передать вручную; интернет для установки не нужен |
| Скачать готовый выпуск с GitHub | Нажать кнопку установки совместимого комплекта, прочитать результат, перезапустить WinUp | WinUp найдёт выпуск, скачает и проверит его | Владелец сначала должен выпустить проверенный комплект |
| GitHub готовит кандидат, подпись остаётся на ПК | Владелец запускает `tools/publish-tested.cmd`; остальные нажимают обновление в WinUp | GitHub ищет поддерживаемые новые зависимости и проверяет их; локальный инструмент проверяет происхождение файлов, пересобирает и подписывает выпуск | Если тесты или проверка происхождения не прошли, выпуска нет. Несовместимость исправляет разработчик |
| GitHub получает ключ подписи | Можно выпускать автоматически после тестов | CI сам подписывает файлы | Компрометация аккаунта или процесса CI может дать право подписать поддельное обновление. Этот вариант не включён |

Для двух человек удобнее третий вариант: брату достаточно кнопки в WinUp, владельцу — одной команды выпуска. Файл `.wup` остаётся запасным способом без GitHub.

## Что обновляется

- Расширение, криптографические библиотеки ключей доступа, список доменных границ и файловый движок входят в подписанный совместимый комплект. После установки нужен перезапуск WinUp, а после изменения расширения — его перезагрузка в браузере и обновление страницы.
- KeePass обновляется отдельной проверкой официального крипто-ядра.
- WinFsp — установленный драйвер Windows. Для его установки/обновления может понадобиться разрешение администратора и перезапуск Windows.
- Основной `WinUp.exe` заменяется файлом нового выпуска при закрытой программе. Комплект компонентов сам по себе не заменяет основной EXE.
- Автоматический кандидат обновляет только явно предусмотренные зависимости. Полная замена Java/Cryptomator и изменение протокола требуют подготовки согласованного движка и тестов.

## Кто проверяет и кто чинит

GitHub Actions запускает написанные нами функциональные проверки: сборка, сохранение и повторное открытие учебной базы, интерфейс, установщики, шифрованные файлы и подключение диска. Отдельно расширение проверяется в настоящих браузерах в Sandbox.

Тесты умеют обнаружить предусмотренные ошибки. Они не умеют самостоятельно переписать сломавшийся код и не доказывают отсутствие всех ошибок. При несовместимости выпуск останавливается; исправления делает разработчик. Углублённый аудит атаками — отдельная отложенная работа, он не заменён зелёной отметкой CI.

## Риски GitHub и защита

Полностью исключить риски невозможно. Их можно уменьшить:

1. Закрытый ключ выпусков хранится только на вашем ПК, защищён Windows DPAPI. В GitHub Actions его нет. Это не пароль и не ключ вашей базы.
2. Один контроль GitHub недостаточен для подписи: локальный выпуск сверяет код с доверенной местной копией, повторно получает разрешённые библиотеки из официальных источников и проверяет их подписи. Подменённый код не должен пройти эту сверку.
3. Действия CI закреплены на конкретных коммитах; рабочие задания получают минимальные права. Секреты базы и локальный ключ не публикуются.
4. Для аккаунта GitHub стоит включить 2FA/passkey, сохранить резервные коды отдельно и ограничить доступ к репозиторию. Это действие владельца аккаунта; программа не может выполнить его вместо вас без участия в настройке входа.
5. Изменения основной ветки должны проходить обязательные проверки. Зелёные тесты не дают внешнему человеку ключ подписи.
6. Отдельно сохраните резервную копию базы и защищённого ключа выпуска. DPAPI-файл нельзя просто перенести на другой Windows-аккаунт и ожидать, что он расшифруется. Потеря исходного аккаунта/ПК без пригодного резервного ключа может остановить выпуск будущих обновлений.

Если GitHub недоступен, уже установленный WinUp продолжает работать. Если источник обновлений подменит файл без действительной подписи, установка откажется. Если злоумышленник получит доступ к вашему ПК и ключу подписи, локальное хранение уже не спасёт: это отдельная граница защиты.

Статус «новая версия библиотеки» и «готов новый совместимый комплект» различаются. Если библиотека уже обновилась у своего автора, а совместимый комплект ещё не выпущен, WinUp показывает необходимость подготовить комплект; повторное нажатие не может само исправить несовместимость.

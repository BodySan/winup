# WinUp 1.18.2

Исправлены проблемы запуска программ и подключения к Windows, отмеченные в дополнительных отчётах безопасности.

- Параметры `.cmd` и `.bat` больше не выполняют дополнительные команды. Обычные значения, включая пробелы, поддерживаются. Команды с `&`, перенаправлением, подстановкой переменных и другими управляющими символами нужно помещать в сам сценарий.
- PowerShell и командный интерпретатор запускаются из системной папки Windows. Параметры PowerShell и MSI передаются с сохранением границ отдельных значений.
- Установка с правами администратора получает одноразовое разрешение от основного окна WinUp. Оно предназначено конкретному запущенному процессу и содержит снимок выбранного списка. Переданный снаружи хэш `apps.json` больше не разрешает установку.
- При ошибке подключения провайдера WinUp не устанавливает автоматически пакет из прежней папки. Если перенос подключения не завершился, откройте прежнюю копию WinUp и подключите её заново.
- После обновления WinUp вспомогательная программа уже подключённого провайдера обновляется при обновлении списка ключей. Повторное подключение и изменение доверия Windows для этого не требуются.
- Проверка сайтов обращается только к публичным HTTPS-адресам. Внутренние, локальные и служебные адреса проверяйте в браузере. Запрос использует HEAD, не следует перенаправлениям и не передаёт пароли, cookies или данные прокси. Если сайт не поддерживает такую проверку, WinUp предлагает открыть его вручную.
- Строки системного провайдера проверяются до создания больших объектов, а идентичность процесса — через один удерживаемый дескриптор.
- Файловый помощник пересобран из опубликованных исходников. Проверка его побайтовой воспроизводимости добавлена в GitHub Actions.

Инструкция обновлена. Форматы базы, файловых хранилищ и ключей доступа не менялись.

Для этих исправлений требуется обновить сам `WinUp.exe`: установка одного комплекта компонентов не заменяет программу.
